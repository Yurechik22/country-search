# DESIGN

Живой поиск стран по API [countries.dev](https://countries.dev/docs). Главная задача — чтобы на экране всегда был ответ на **последний** введённый запрос, даже если сеть отвечает в произвольном порядке.

Схема слоёв:

```
input ──► debounce (400 мс) ──► SearchController ──► createCachedSearch ──► searchCountries ──► fetch
                                   │  state                                     │
                                   ▼                                            ▼
                                AppView (DOM)                          mapCountryResponse
```

Логика (`src/api`, `src/domain`, `src/search`, `src/history`, `src/utils`) не знает о DOM; всё, что трогает DOM, лежит в `src/ui` и `src/main.ts`.

---

## 1. Отмена устаревших запросов

**Проблема.** Пользователь печатает `sw`, потом быстро стирает и печатает `n`. Запрос `sw` медленный, `n` — быстрый. Если просто ждать оба ответа, `sw` придёт последним и затрёт правильный результат для `n` (race condition).

**Решение** — `SearchController` (`src/search/search-controller.ts`):

1. На каждый запрос создаётся свой `AbortController`, он хранится в `this.pending`.
2. Перед новым запросом вызывается `cancelPending()` → `pending.abort(new DOMException(..., 'AbortError'))`.
   Кроме того, `main.ts → handleQueryChange` вызывает `cancelPending()` **на каждое изменение input**, ещё до срабатывания debounce: как только текст поменялся, старый ответ уже не нужен.
3. `fetch` с отменённым сигналом реально обрывает HTTP-запрос (в DevTools → Network он помечен как `(canceled)`) и реджектит промис с `AbortError`.
4. В `catch` ошибка классифицируется (`classifyError`, `src/api/errors.ts`):
   - `aborted` — это наша собственная отмена, **ничего не показываем**;
   - `timeout` — сработал `AbortSignal.timeout`, показываем ошибку;
   - `http` / `network` — показываем ошибку с кнопкой **Retry**.
5. Дополнительная страховка — `isCurrent(request)`: состояние меняет только тот запрос, который сейчас в `this.pending`. Это защищает, даже если транспорт проигнорировал abort (см. второй тест в `tests/race-condition.test.ts`).

**Почему именно abort, а не только «игнорировать старые ответы».** Игнорирование решает только видимую часть проблемы: браузер всё равно скачивает и парсит ненужные ответы, держит соединения (у HTTP/1.1 их ~6 на домен — лишние запросы могут задерживать нужный), тратит трафик и батарею. `abort()` освобождает сеть сразу.

**Таймаут** — `withTimeout(signal, ms)` (`src/utils/abort.ts`) объединяет пользовательский сигнал с `AbortSignal.timeout(ms)` через `AbortSignal.any`, а в старых браузерах — через ручной fallback `anySignal`. Причина отмены сохраняется (`signal.reason`), поэтому `TimeoutError` и `AbortError` различаются без дополнительных флагов.

**404** — у countries.dev означает «ничего не найдено». `searchCountries` (`src/api/countries-api.ts`) возвращает `[]`, контроллер показывает нейтральное состояние `empty`, а не ошибку. Любой другой `!response.ok` → `HttpError` со статусом.

## 2. Задержка debounce: 400 мс

`SEARCH_DEBOUNCE_MS = 400` (`src/config.ts`).

- Средний интервал между нажатиями при обычном наборе — 150–300 мс. 400 мс почти всегда «переживает» паузу внутри слова, так что запрос уходит, когда человек остановился, а не на каждой букве.
- При этом 400 мс воспринимается как мгновенная реакция: порог, после которого задержку замечают, — около 0.5–1 с.

**Если убрать debounce** — запрос на каждую букву: `n`, `no`, `nor`, `norw`… Большинство из них сразу отменяются, но всё равно создают нагрузку на API (риск rate limit), мигание индикатора загрузки и результатов, лишний трафик. Отмена спасла бы корректность, но не эффективность.

**Если сделать сильно больше (например, 2 с)** — интерфейс кажется «тормозным»: пользователь закончил печатать и ждёт без обратной связи; кажется, что поиск сломан, человек начинает перепечатывать запрос.

Debounce и abort решают разные задачи: debounce уменьшает **количество** запросов, abort гарантирует **корректность** при оставшихся.

## 3. Сложность (Big O)

### `mapCountryResponse` (`src/domain/map-country.ts`)

Для одной страны: **O(L + C + B)** по времени и памяти, где L — число языков, C — валют, B — граничащих стран (каждый массив проходится один раз через `map`/копирование; остальные поля — O(1)). Для ответа из n стран: **O(n · k)**, где k — средний размер вложенных массивов (на практике k ≤ ~15, т.е. фактически O(n)). Функция чистая: вход не мутируется (есть тест).

### Кэш `createCachedSearch` (`src/search/cached-search.ts`)

- Нормализация ключа (`trim().toLowerCase()`): **O(q)**, q — длина запроса.
- Поиск/вставка/удаление в `Map`: **O(1)** в среднем.
- Подписка на in-flight запрос и отписка: **O(1)** (счётчик подписчиков, без массивов слушателей).
- Повторный запрос из кэша: O(q), без сети.
- Память: **O(K · R)**, K — число закэшированных запросов, R — размер результата. Ошибки не кэшируются, поэтому кэш не «залипает» на сбое.

Каждый вызывающий передаёт **свой** сигнал: его abort реджектит только его промис. Общий запрос отменяется лишь когда отписались все (`subscribers === 0`), — тогда в Network он тоже будет `(canceled)`.

### История (`src/history/search-history.ts`)

`add`: **O(h)**, h ≤ 8 (лимит), т.е. O(1) по сути.

## 4. Принципы чистого кода

| Принцип                                           | Где                                                                                                                                                                                                                                     |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Single Responsibility**                         | `searchCountries` только ходит в сеть; `mapCountryResponse` только преобразует данные; `SearchController` только управляет жизненным циклом запроса; `AppView` только рисует состояние.                                                 |
| **Разделение логики и DOM**                       | Ни один файл вне `src/ui` и `src/main.ts` не обращается к `document`. Контроллер общается с UI через колбэк `onChange(state)` (`src/search/search-controller.ts`).                                                                      |
| **Состояние как размеченное объединение**         | `SearchState` (`src/search/search-state.ts`) — `idle / loading / success / empty / error`. Невозможные комбинации (например, «загрузка + ошибка») не выражаются типом; `switch` в `AppView.render` проверяется компилятором на полноту. |
| **Dependency Injection**                          | Контроллер получает `search: SearchFn` снаружи, `SearchHistory` — `KeyValueStorage`. Поэтому тесты подставляют моки без DOM и сети, а кэш подключается в `main.ts` одной строкой.                                                       |
| **Pure functions**                                | `mapCountryResponse`, `classifyError`, `describeError`, `formatNumber`, `formatList`.                                                                                                                                                   |
| **Говорящие имена и отсутствие магических чисел** | `SEARCH_DEBOUNCE_MS`, `REQUEST_TIMEOUT_MS` (`src/config.ts`), `NOT_FOUND` (`countries-api.ts`).                                                                                                                                         |
| **Fail-safe**                                     | `SearchHistory` переживает битый JSON, приватный режим и переполнение storage; `mapCountryResponse` даёт безопасные значения по умолчанию для отсутствующих полей.                                                                      |
| **Безопасность DOM**                              | Все узлы создаются через `el()` (`src/ui/dom.ts`) с `textContent`; `innerHTML` / `insertAdjacentHTML` запрещены правилом ESLint `no-restricted-properties`.                                                                             |
| **TDD**                                           | Для `debounce`, `mapCountryResponse`, `searchCountries`/`HttpError`, классификации ошибок, контроллера, кэша и истории сначала идёт коммит с падающими тестами, затем — реализация.                                                     |
